# Multi-Language Support Implementation

This document describes the internationalization (i18n) implementation in DocKit, which supports English, Simplified Chinese, Traditional Chinese (Taiwan), Brazilian Portuguese, Japanese, Korean, and Spanish.

## Overview

The multi-language support is implemented with [vue-i18n](https://vue-i18n.intlify.dev/).

## Language Files

All language files are located in `src/lang/`:

- **`index.ts`**: Main i18n configuration, locale detection, and initialization
- **`enUS.ts`**: English (US) translations — the key source of truth
- **`zhCN.ts`**: Chinese Simplified translations
- **`zhTW.ts`**: Traditional Chinese (Taiwan) translations (community contribution, [dockit#540](https://github.com/geek-fun/dockit/issues/540))
- **`ptBR.ts`**: Brazilian Portuguese translations
- **`jaJP.ts`**: Japanese translations
- **`koKR.ts`**: Korean translations
- **`esES.ts`**: Spanish translations

## Language Detection and Storage

The language preference is:

1. **Stored in localStorage** with key `'lang'`, falling back to the persisted app-store `languageType` so a choice made in Settings survives restarts
2. **Auto-detection**: If set to `'auto'` (the default), follows the system language (`navigator.language`):
   - `zh-TW` / `zh-HK` / `zh-MO` / `zh-Hant` → `zhTW`
   - other `zh-*` → `zhCN`
   - `pt-*` → `ptBR`, `ja*` → `jaJP`, `ko*` → `koKR`, `es*` → `esES`
   - anything else → `enUS`

Users can override this in **Settings → Basic → Language**. `fallbackLocale` is `enUS`, so a missing key in any locale renders the English string instead of a raw key.

`getDocLanguage()` maps the active locale onto `'en' | 'cn'` for content that only ships in English or Chinese (docs links, agent prompt language); every non-Chinese locale resolves to `'en'`.

## Adding a New Language

1. Copy `src/lang/enUS.ts` to `src/lang/{locale}.ts` (locale codes follow the `zhCN` / `ptBR` style, e.g. `frFR`).
2. Translate the values. Keep brand names, SQL keywords, code identifiers, keyboard key names, and interpolation placeholders (`{name}`) exactly as they are. Keep the `setting.*` language-name keys as native names.
3. Register the file in `src/lang/index.ts`: import it, add the locale code to the `AppLocale` type and `isAppLocale`, add it to the `messages` object, and extend `detectFromNavigator()` so the system language maps to it.
4. Add the enum value to `LanguageType` in `src/store/appStore.ts` and an entry to `langTypes` in `src/views/setting/components/basic.vue`.
5. Add the locale to `tests/i18nParity.test.ts`.
6. Run `npm run test:ci` — the parity test must pass.

## Testing

`tests/i18nParity.test.ts` asserts every locale file carries exactly the `enUS` key set. CI fails on drift; at runtime, missing keys fall back to English rather than showing raw keys.
